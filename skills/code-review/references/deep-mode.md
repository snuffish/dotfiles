# Code Review Deep Mode — Axis Briefs & Aggregation

On-demand reference for [SKILL.md](../SKILL.md) › *Deep Mode*. Follow [fan-out.md](../../_modules/fan-out.md) for the brief contract and aggregation rules.

---

1. **Complete Steps 1–3 in the lead agent first** — base resolved, non-empty diff confirmed, snapshot(s) created (*Step 1b*), Spec source fetched, Standards sources listed (and profile checklists/catalogs read from `origin/<default>`).
2. **Spawn one sub-agent per selected axis (*Step 5a*) in parallel on Sonnet** (`fan-out` › *Brief contract*; in Claude Code pass `model: "sonnet"` to the Agent tool, elsewhere use the host's default). The verifier in step 4 runs on the session model. Run at most four axis sub-agents, so the verifier makes five: with five or six axes on, append Security's prompt to the Correctness brief, then Drift's to the Standards brief; their findings keep their own axis tag. Each brief includes `git -C <snapshot> diff <base>...HEAD`, the commit list, the snapshot's `[worktree-context]` block per repo, and its axis prompt:
   - **Correctness**: *"Find bugs, edge cases, race conditions, security, and performance issues in this diff. Read whole files where the diff lacks context. For each: `path:line`, the failing path as a concrete sequence, proposed severity (🔴/🟡/🟢). Return only the findings, one entry each; no restated diff."*
   - **Standards**: include the Step 3 Standards source files, any profile checklist sections mapped to Standards, and the [smell-baseline.md](smell-baseline.md) table pasted in full. *"Report every place the diff violates a documented standard — cite the source file and rule — and any baseline smell you spot, labelled as a judgement call. A documented repo standard overrides the baseline. Check the listed cross-repo contracts on both sides. Skip anything tooling enforces. Return only the findings, one entry each; no restated diff."*
   - **Spec**: include the fetched spec/AC text (plus any profile checklist sections mapped to Spec). *"Report: (a) requirements missing or partial; (b) behaviour in the diff that wasn't asked for; (c) requirements that look implemented but where the implementation looks wrong. Quote the spec line for each. Return only the findings, one entry each; no restated diff."* Skip this sub-agent when there is no Spec source, and say so.
   - **Security**: *"Find authentication, authorization and data-exposure defects in this diff: missing or wrong access or ownership checks, protected data reaching a caller who may not see it, bypassed query filters, injection, secrets in code or logs, unvalidated input. For each: `path:line`, the caller and the concrete path to the defect, proposed severity (🔴/🟡/🟢). Return only the findings, one entry each; no restated diff."*
   - **Tests**: include the repo's testing rules from Step 3. *"For each behaviour this diff adds or changes, name the test that exercises it as `path:line`, or report it as uncovered. Also report failing branches, guards and rollback paths no test reaches, assertions too weak to catch the defect the test is named for, and deleted tests without a replacement. Proposed severity for each. Return only the findings, one entry each; no restated diff."*
   - **Drift**: *"Report every doc, skill, rulebook, code comment and checked-in generated artifact (API snapshot, generated client, route tree) that no longer matches the code at head because of this diff, including references to renamed, moved or deleted symbols. Cite both sides as `path:line`, proposed severity for each. Return only the findings, one entry each; no restated diff."*
3. **Aggregate** (`fan-out` › *Aggregation*): deduplicate findings across axes (keep the axis that owns the root cause), assign final severities within each axis, and confirm no citation points into a snapshot directory.
4. **Independent verifier.** Spawn one fresh read-only sub-agent (`fan-out` › *Brief contract*) that saw none of the axis reasoning. Its brief holds the snapshot's `[worktree-context]` block per repo, the diff command, any profile lessons catalog, and the deduplicated 🔴/🟡 list stripped to number, axis, claim and `path:line` (Spec findings keep their quoted spec line). Prompt: *"You are a skeptic. For each finding, re-open the cited `path:line` at the snapshot head and try to refute it: check callers, guards, validators, query filters, config and the lessons catalog. Return one entry per finding: number, verdict (Verified / Plausible / Refuted), the evidence as `path:line` plus a quoted snippet, and for Plausible the exact command that would confirm it. Return every finding you were given."* The criterion is that every finding comes back with a verdict and evidence; re-brief for any it missed.
5. **Reconcile, then Step 6.** Run **Step 6 — Verify** yourself on every 🔴/🟡 with the verifier's verdict as evidence. Where you and the verifier disagree, re-read the code, keep the side the code supports, and record the resolution in *Review Context* › **Mode & Blind-spot pass** as `verifier: N verified, N plausible, N refuted, N overruled`. Findings first raised in *Step 6b* (`feedback`) or *Step 6c* (blind-spot pass) go through Step 6 in the lead agent. Then write *Feature in Brief* yourself, emit the artifact and chat link block, and remove the snapshot(s).
